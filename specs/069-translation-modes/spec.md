## Решения владельца

- **D-1 (2026-11-09).** У операции «перевод» два режима. **«Стандарт» — по умолчанию:** первый проход текущей
  моделью (`openrouter:google/gemini-3.1-flash-lite-preview`, литературная интенсивность, как сейчас), второй проход
  `literary_polish` моделью `openrouter:anthropic/claude-haiku-5.5` (bake-off C: литературность 4,0 / 4,05, верность
  4,35 / 4,35, кальки вдвое меньше, чем у одного прохода; книга ≈ 0,8–1,2 $). **«Качество» — опция:** один проход
  `openrouter:google/gemini-3.7-flash`, `reasoning.effort = low`, интенсивность `conservative` (раунд 4: литературность
  4,50 / 4,68, верность 4,22 / 3,90; книга ≈ 1,4–1,9 $). 3.8-flash отклонена (качество как у 3.7, дороже), Sonnet 5.5
  (E) — по цене.
- **D-2 (2026-11-09).** При загрузке документа пользователь видит примерную цену обоих режимов; после прогона —
  фактическую рядом с оценкой.
- **D-3 (2026-11-08, уточнено D-1).** Модели режимов задаются конфигом по итогу замеров, а не ручкой в интерфейсе
  (исключение из «никаких ручек» — только выбор режима, потому что он меняет цену и время, как режимы картинок).

## Что измерено (bake-off FR-017, две главы: RM гл. 3 и Money гл. III)

- **Цена рассуждения.** Приложение не передаёт параметр `reasoning`; по умолчанию gemini-3.7-flash тратит на
  рассуждение 63–68 % вывода, часть ответов обрывается без текста (`incomplete`, 4 из 16 на RM). `effort: low` —
  0 токенов рассуждения, 0 обрывов, цена главы −53–57 %. Промежуточного уровня нет: `medium` думает не меньше
  умолчания, бюджет `max_tokens` 256–2048 работает как `low`; отключить рассуждение нельзя (HTTP 400 «Reasoning is
  mandatory»).
- **Вольности сильных моделей.** С литературной интенсивностью 3.7/3.8 переписывают как редактор: 105–138
  добавлений и сдвигов смысла на 60 абзацев против 23–50 у текущей модели; сдержанная интенсивность на `low` сокращает
  их вдвое (62 / 91) и поднимает верность (RM 3,65 → 4,22, Money 3,50 → 3,90). Чисел не меняет ни одна конфигурация.
- **Бюджеты вывода подобраны под flash-lite.** Haiku 5.5 тратит ≈ 3× токенов на тот же русский текст: вызов
  глоссария упёрся в `max_output_tokens` 6016 и вернул 4 термина вместо ≈ 65 (вариант D, Money); у Gemini по
  умолчанию выход включает рассуждение, обрывы — платные повторы.
- **Примечания в конце главы остаются по-английски** у всех конфигураций Gemini на Money гл. III (p0102–p0111,
  7 пар): 1993–2036 символов при пороге шлюза 2000 (`pipeline/quality_gate_text_detectors.py:29-30`) — доставка заблокирована
  у четырёх конфигураций из шести, у текущей модели эти абзацы переведены. Механизм не обследован.
- **Второй проход в bake-off шёл в обход продукта** (отладочный харнес: операция `edit` ru→ru над DOCX первого
  прохода с подменой промпта); повторный импорт DOCX дал свои артефакты (рисунки получили уровень заголовка, две
  пары абзацев склеились) — в продукте второй проход не должен проходить через импорт.
- **Дефекты шлифовки Haiku**, пойманные на двух главах: одно слово со смешанным алфавитом («mеtался», поймано
  `mixed_script_terms_present`), нумерация пунктов «2.», «3.» → «1.», потерянное «23 страны», отдельные ослабления.

## Requirements *(mandatory)*

- **FR-001 Режим перевода — контракт конфига.** `resources/config.toml` получает таблицу режимов перевода:
  `[translation_modes.standard]` и `[translation_modes.quality]`, у каждого — модель первого прохода, необязательная
  модель второго прохода, необязательный уровень рассуждения на модель, интенсивность первого прохода; ключ
  `translation_mode_default = "standard"`. Резолвер читает таблицу по правилу 066 (сначала TOML, затем переменная
  окружения; `config_key_ignored` для неизвестных ключей). Run-профиль раннера получает поле `translation_mode`
  (`standard` | `quality` | `single` — последний = нынешний один проход, только для регрессионных бенчмарков, в UI его
  нет). Операции `edit` и `audiobook` режимы не затрагивают.
- **FR-002 UI.** Для операции «перевод» в боковой панели — выбор режима из двух вариантов (`st.radio`), по умолчанию
  «Стандарт»; подпись каждого варианта несёт оценку цены из FR-006 («≈ 0,8–1,1 $»), пока документ не загружен — без
  цены. Выбор модели в «Дополнительно» для перевода не показывается: модели задаёт режим (D-3); для `edit` и
  `audiobook` всё как сейчас. Тексты — в `ui/locales/{ru,en}.json`. Раскладка — штатными примитивами Streamlit
  (контракт AGENTS.md).
- **FR-003 Параметр рассуждения.** Когда у модели режима задан уровень рассуждения, КАЖДЫЙ текстовый вызов прогона
  с этой моделью (блоки, повторы, лестница деградации, глоссарий) несёт `reasoning={"effort": <уровень>}` — через
  единую точку `call_responses_create_with_retry` или сборку запроса, так чтобы ни один путь не обходил её; путь
  Chat Completions (запасной OpenRouter) несёт эквивалент. Отказ провайдера от параметра — штатный механизм
  `drop_rejected_optional_param` с WARNING, прогон не падает. Бухгалтерия (`model_accounting`) записывает токены
  рассуждения (`output_tokens_details.reasoning_tokens`) по стадиям; отчёт и `run_summary` их показывают.
- **FR-004 Второй проход «литературная шлифовка».** В режиме с моделью второго прохода каждый блок после принятого
  первого прохода (маркеры проверены) отправляется второй раз: системный промпт `prompt_variant="literary_polish"`,
  целевой язык → целевой язык, с тем же контекстом документа и глоссарием прогона, что у первого прохода (термины не
  должны «уплыть»), с маркерами абзацев первого прохода. Проход идёт внутри конвейера блока — без повторного импорта.
  Проверка результата по ФОРМЕ, без словарей (Конституция VII): (а) маркеры и число абзацев — как у первого прохода,
  иначе весь блок остаётся текстом первого прохода; (б) по абзацу — откат к тексту первого прохода, если шлифовка
  изменила мультимножество цифр, добавила слово со смешанным алфавитом, которого не было в первом проходе, изменила
  префикс нумерации пункта, потеряла маркер сноски или вышла за границы отношения длин к первому проходу (границы — из
  распределения bake-off C, называются в `plan.md`). Каждый откат — событие `literary_polish_paragraph_rolled_back` с
  причиной; итог блока — счётчики в отчёте. Ошибка или исчерпание попыток второго прохода не роняет блок: остаётся
  первый проход, WARNING. Стадия бухгалтерии — `literary_polish`.
- **FR-005 Примечания в конце главы.** Обследование до правила: почему конфигурации Gemini оставляют p0102–p0111
  Money гл. III по-английски, а текущая модель их переводит (форма абзацев, их роль/регион в задании блока, правило 12
  и D1 063 о библиографии, ответ модели — на записанных данных bake-off). По итогу — правка по форме (промпт, роль
  или учёт шлюза) с замером на тех же главах; шлюз `untranslated_body_text` не ослабляется вслепую.
- **FR-006 Бюджеты вывода с учётом модели.** `_estimate_max_output_tokens` и `glossary_max_output_tokens` считают
  бюджет из коэффициента «токенов вывода на символ источника» для данной модели (тот же, что у оценщика FR-007), а не из
  константы под flash-lite; потолок `_MODEL_OUTPUT_TOKEN_CEILING` и лестница деградации сохраняют свои инварианты
  (`_LADDER_BUDGETABLE_SOURCE_CHARS` выводится из потолка). Замер: вызов глоссария Haiku на Money гл. III возвращает
  полный список, обрывов `incomplete` на 3.7 `low` 0.
- **FR-007 Оценка цены (новый модуль, не бухгалтерия).** `pipeline/cost_estimate.py` (имя уточняется в `plan.md`):
  вход — подготовленный документ (символы источника по блокам, число блоков, размер системного промпта и контекста,
  число вызовов глоссария) и конфиг режима; коэффициенты «токенов ввода/вывода на символ» по паре (модель, стадия);
  начальные значения — из замеренных прогонов (таблица с происхождением каждой цифры: прогон, дата), затем
  САМОКАЛИБРОВКА: после каждого прогона фактические токены по стадиям из бухгалтерии обновляют коэффициенты модели
  (`.run/`, сглаживание); цены — из списка моделей OpenRouter (`/api/v1/models`), кеш в `.run/` с давностью, без сети —
  последний кеш, без кеша — «цена неизвестна». Результат — вилка: нижняя граница учитывает скидку провайдера за кеш
  промпта (на полных книгах 21–24 %, тоже калибруется), верхняя — по прайсу. `model_accounting` остаётся «никогда не
  оценивает»: оценка живёт отдельно и не смешивается с фактом. После прогона — событие `cost_estimate_vs_actual`
  (оценка, факт, отклонение) и строка в UI рядом с результатом.
- **FR-008 Замер (платный, после кода).** Полный прогон Money и RM в обоих режимах через канонический раннер (≈ 2 × (1
  + 1,7) $ ≈ 5–6 $ — сумму подтверждает владелец перед запуском); слепое чтение тех же 60 абзацев двух глав против
  данных bake-off; оценка цены против факта.

## Success Criteria *(mandatory)*

- **SC-001**: режим «Стандарт» на двух главах bake-off — литературность и верность не ниже bake-off C в пределах шума
  одного рецензента (±0,15), откатов шлифовки по FR-004 — каждый прочитан, ложных (откат хорошего абзаца) ≤ 10 %.
- **SC-002**: режим «Качество» на двух главах — 0 токенов рассуждения, 0 обрывов `incomplete`, качество как в раунде 4
  (±0,15).
- **SC-003**: Money гл. III доставляется в обоих режимах (шлюз не блокирует), без ослабления порога шлюза.
- **SC-004**: глоссарий прогона в обоих режимах — без обрезанных вызовов; число терминов в пределах ±15 % от текущей
  модели на тех же главах.
- **SC-005**: оценка цены при загрузке попадает в вилку или отклоняется от факта не более чем на 25 % на полных книгах
  FR-008; после второго прогона той же модели (калибровка) — не более чем на 15 %.
- **SC-006**: `edit` и `audiobook` побайтно не меняются (ни запросы, ни промпты); прогон с `translation_mode = single`
  повторяет нынешний перевод (тот же запрос, без параметра рассуждения).
- **SC-007**: полный прогон тестов зелёный; ревью Codex спеки до кода и приёмочное ревью по всем затронутым
  поверхностям до слияния в `main`.

## Non-goals

- **Пакетный API (`:batch`, −50 %)** — не строится: он асинхронный (ответы через минуты–часы), интерактивному UI не
  подходит; вернуться можно отдельной спекой для фоновых прогонов.
- **Отклонённые конфигурации bake-off** — не возвращаются без нового замера: B (шлифовка той же flash-lite — не
  улучшает, ухудшает верность), D (Haiku одним проходом — не лучше A, заблокирован на Money), E (Sonnet — цена),
  3.8-flash (качество как у 3.7, дороже), `reasoning.effort = medium` (думает не меньше умолчания).
- Не выносить выбор модели режима, уровня рассуждения или интенсивности в интерфейс (D-3); не держать ручных
  поправок цены.
- Не трогать модели и промпты `edit`/`audiobook`, картинок, reader cleanup.
- Не вводить словари и литералы книг (Конституция VII): проверки отката FR-004 и правка FR-005 — по форме.
- Не менять шлюз качества ради прохождения (FR-005 — сначала механизм).

## Anti-regression

1. `single` = нынешний перевод: тот же запрос (без `reasoning`), тот же промпт, те же бюджеты для
   `gemini-3.1-flash-lite-preview` (коэффициент FR-006 для неё воспроизводит `len // 3 * 4`).
2. Инварианты 063–068 на прогонах FR-008: числа, маркеры сносок, заголовки уровней 1–2, склейки ячеек, указатель
   (дубли/потери 0), события блока в `app.log` прогона.
3. Второй проход не проходит через импорт и не меняет структуру: число абзацев, роли, уровни заголовков, маркеры —
   как у первого прохода; несоответствие → откат блока, не падение.
4. `model_accounting` не получает ни одной оценочной цифры; факт и оценка — в разных полях и событиях.
5. Канонические пути (AGENTS.md): тесты — `scripts/test.sh` через WSL, прогоны — `scripts/run-real-document-validation.sh`;
   `.run/` и `.env` вне git; полный прогон в главном дереве и пустой `git status --porcelain` перед «зелёным».

## Assumptions

- Цены OpenRouter на 2026-11-09 (вход / выход за 1 млн): gemini-3.1-flash-lite-preview 0,25 / 1,50, claude-haiku-5.5
  0,10 / 0,50, gemini-3.7-flash 0,75 / 3,75. Оценки «книга ≈ …» в D-1 — экстраполяция с двух глав двумя способами
  (63, Changelog), не замер; FR-008 их проверяет.
- Слепое чтение — один рецензент (Sonnet 5.5) на главу и раунд; разница меньше ≈ 0,15–0,4 балла — шум.
- `reasoning.effort = low` у gemini-3.7-flash сейчас даёт 0 токенов рассуждения; если провайдер изменит поведение,
  бухгалтерия FR-003 это покажет.
