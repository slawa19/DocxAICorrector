## Решения владельца

- **D-1 (2026-11-09).** У операции «перевод» два режима. **«Стандарт» — по умолчанию:** первый проход текущей
  моделью (`openrouter:google/gemini-3.1-flash-lite-preview`, литературная интенсивность, как сейчас), второй проход
  `literary_polish` моделью `openrouter:anthropic/claude-haiku-5.5` (bake-off C: литературность 4,0 / 4,05, верность
  4,35 / 4,35, кальки вдвое меньше, чем у одного прохода; книга ≈ 0,8–1,2 $). **«Качество» — опция:** один проход
  `openrouter:google/gemini-3.7-flash`, `reasoning.effort = low`, интенсивность `conservative` (раунд 4: литературность
  4,50 / 4,68, верность 4,22 / 3,90; книга ≈ 1,4–1,9 $). 3.8-flash отклонена (качество как у 3.7, дороже), Sonnet 5.5
  (E) — по цене.
- **D-2 (2026-11-09).** При загрузке документа пользователь видит примерную цену обоих режимов; после прогона —
  фактическую рядом с оценкой.
- **D-3 (2026-11-08, уточнено D-1).** Модели режимов задаются конфигом по итогу замеров, а не ручкой в интерфейсе
  (исключение из «никаких ручек» — только выбор режима, потому что он меняет цену и время, как режимы картинок).

## Что измерено (bake-off FR-017, две главы: RM гл. 3 и Money гл. III)

- **Цена рассуждения.** Приложение не передаёт параметр `reasoning`; по умолчанию gemini-3.7-flash тратит на
  рассуждение 63–68 % вывода, часть ответов обрывается без текста (`incomplete`, 4 из 16 на RM). `effort: low` —
  0 токенов рассуждения, 0 обрывов, цена главы −53–57 %. Промежуточного уровня нет: `medium` думает не меньше
  умолчания, бюджет `max_tokens` 256–2048 работает как `low`; отключить рассуждение нельзя (HTTP 400 «Reasoning is
  mandatory»).
- **Вольности сильных моделей.** С литературной интенсивностью 3.7/3.8 переписывают как редактор: 105–138
  добавлений и сдвигов смысла на 60 абзацев против 23–50 у текущей модели (раунды 2–4); сдержанная интенсивность на
  `low` сокращает их на 41,5 % (RM, 106 → 62) и 34,1 % (Money, 138 → 91) и поднимает верность (RM 3,65 → 4,22, Money
  3,50 → 3,90; раунд 4, один рецензент на главу). Цифры не меняет ни одна конфигурация, но числа, записанные словами,
  меняются: RM G-low p0043 «another four years» → «ещё три года», «a second quarter» → «вторую половину» — цифровые
  проверки этого не видят.
- **Бюджеты вывода подобраны под flash-lite.** Оплаченных токенов вывода на символ доставленного текста: A 0,287 /
  0,289, Haiku C 0,978 / 0,829, D 0,990 / 1,193 (RM / Money; агрегаты включают повторные вызовы) — в 2,9–4,1 раза
  больше; вызов глоссария Haiku упёрся в `max_output_tokens` 6016 и вернул 4 термина вместо ≈ 65 (D, Money). Нынешний
  лимит блока `max(len // 3 * 4, 512)` ≈ 1,333 токена на символ источника при расходе A ≈ 0,3 — запас для A большой.
- **Примечания в конце главы Money гл. III (p0102–p0111)** — смешанный аппарат: часть записей — библиография (по D1
  063 остаётся на языке источника), часть — содержательные комментарии. У Gemini часть комментариев остаётся
  по-английски (G-low-cons p0103 — «The CIA Factbook 2012 estimates global GDP…» целиком; у A переведено), часть
  переведена (p0105–p0106, p0110); шлюз `untranslated_body_text` считает смешанный фрагмент целиком (p0110 —
  1 344 символа, с p0104 — 663, итого 2 007 при пороге 2 000, `pipeline/quality_gate_text_detectors.py:29-30`, ветка URL
  `:76` возвращает результат раньше библиографических признаков). Заблокированы G-low, F-low, G-low-cons, G-def-cons
  (2 001–2 036 символов); G по умолчанию прошёл с 1 993, F — с 663. A, со своей стороны, переводит имена авторов,
  которые по D1 должны оставаться.
- **Второй проход в bake-off шёл в обход продукта** (отладочный харнес: операция `edit` ru→ru над DOCX первого
  прохода с подменой промпта); повторный импорт DOCX дал свои артефакты (рисунки получили уровень заголовка, две
  пары абзацев склеились) — в продукте второй проход не должен проходить через импорт.
- **Дефекты шлифовки Haiku (C)**, найденные на двух главах: слово со смешанным алфавитом «mеtался» (RM, поймано
  `mixed_script_terms_present`); английское слово целиком — «они, несомненно, will включать» (Money p0096; цифры,
  маркеры и длина 1,0065 в норме); нумерация пунктов «2.», «3.» → «1.»; отдельные ослабления. Перевод числа в слова —
  «23 страны» → «Двадцать три страны» (Money p0032), «16-й» → «шестнадцатой» (RM) — значение сохранено, но цифровая
  проверка его откатила бы: на 207 сопоставимых парах проверки цифр и смешанного алфавита выделяют 6 абзацев, 2 из них —
  такие ложные.
- **Воспроизводимость слепого чтения.** Одни и те же тексты (G и G-low, 60/60 абзацев) в раундах 3 и 4 получили
  литературность Money 3,95 → 4,75 и 3,93 → 4,78, RM 4,50 → 4,42 и 4,35 → 4,60; верность Money 4,25 → 4,00 и 3,72 → 3,50,
  RM 3,85 → 3,62 и 3,87 → 3,65. Сравнивать можно только варианты, прочитанные одним рецензентом в одном раунде;
  выбор D-1 опирается на такие сравнения (раунд 4 — с якорями A, G, G-low).

## Requirements *(mandatory)*

- **FR-001 Режим перевода — контракт конфига и единое разрешение.** `resources/config.toml` получает
  `[translation_modes.standard]` и `[translation_modes.quality]`: модель первого прохода, интенсивность первого прохода,
  уровень рассуждения первого прохода (необязателен), модель второго прохода и её уровень рассуждения (необязательны);
  `translation_mode_default = "standard"`. Резолвер — по правилу 066 (TOML, затем переменная окружения;
  `config_key_ignored` для неизвестных ключей). **Одна функция разрешения** эффективной конфигурации перевода для UI и
  раннера: для `translate` режим ПОБЕЖДАЕТ общие `model`, `editorial_intensity_default` и одноимённые поля run-профиля
  (сейчас их подставляют `ui/_ui.py:615` → `ui/_app.py:844` и `validation/profiles.py:250,381`); конфликт — WARNING с
  именами полей. Run-профиль получает поле `translation_mode` (`standard` | `quality` | `single`); профиль без поля
  разрешается в `translation_mode_default`, как UI; регрессионные профили, которым нужна сопоставимость с прошлыми
  прогонами, получают `single` явно (список — в `plan.md`). `single` = нынешний один проход: та же модель, интенсивность,
  запрос, бюджеты, без `reasoning`; в UI его нет. Эффективные модели, интенсивность и рассуждение обоих проходов
  записываются в runtime-config отчёта. Операции `edit` и `audiobook` режимы не затрагивают; рекомендации настроек
  (`ui/recommended_text_settings.py`) и переходы между операциями проверяются тестами.
- **FR-002 UI.** Для операции «перевод» — выбор режима из двух вариантов (`st.radio`), по умолчанию «Стандарт»; подпись
  каждого варианта несёт оценку цены из FR-007 («≈ 0,8–1,1 $»), до загрузки документа — без цены. Выбор модели в
  «Дополнительно» и виджет интенсивности для перевода не показываются и не влияют на прогон (FR-001); для `edit` и
  `audiobook` всё как сейчас. Тексты — в `ui/locales/{ru,en}.json`; раскладка — штатными примитивами Streamlit.
- **FR-003 Параметр рассуждения — матрица API.** Когда у модели прохода задан уровень, ВСЕ текстовые вызовы этого
  прохода (блоки, повторы, лестница деградации, восстановление пары, глоссарий; для второго прохода — его вызовы)
  несут его; вызовы проверки границ абзацев и картинок — нет (у них свои модели). Матрица: **Responses API**
  (основной путь) — `reasoning={"effort": …}`; **OpenRouter Chat Completions** (запасной путь,
  `_call_chat_completions_create` `_generation.py:2043-2058` собирает запрос заново) — через `extra_body={"reasoning":
  {…}}`; **нативный Anthropic** (`:2184`) — не поддерживается: параметр не передаётся, WARNING (модели режимов идут через
  OpenRouter). Отказ провайдера — удаление вложенного параметра механизмом `drop_rejected_optional_param` (добавить
  `reasoning` в набор удаляемых) с WARNING, прогон не падает. При незаданном уровне и в `single` параметра в запросе нет
  вовсе. Бухгалтерия записывает токены рассуждения: Responses — `output_tokens_details.reasoning_tokens`, Chat —
  `completion_tokens_details.reasoning_tokens`; отсутствие поля — «неизвестно», не ноль; отчёт и `run_summary`
  показывают их по стадиям.
- **FR-004 Второй проход «литературная шлифовка» — контракт.**
  (1) **Что шлифуется:** только абзацы блока со статусом первого прохода `accepted`; `omitted`, `source_restored`,
  `policy_kept_source` и прочие не отправляются и не меняются. Блок без маркеров (одиночный абзац) шлифуется тем же
  путём с одним маркером.
  (2) **Промпт:** `prompt_variant="literary_polish"` с собственным ключом кеша системного промпта (сейчас
  `_get_cached_system_prompt` `block_execution.py:1146` различает только `toc_translate` и `default`) и С контекстом
  документа и глоссарием прогона (сейчас `pipeline/support.py:21` отдаёт контекст только `translate`); промпт шлифовки
  получает правило «записывать числа так же, как в тексте (цифры — цифрами, слова — словами)».
  (3) **Место:** внутри исполнения блока, после принятого первого прохода и до распознавания сохранённого аппарата,
  восстановления сносок и записи реестра (`block_execution.py:2283` и далее) — эти шаги видят итоговый текст; без
  повторного импорта.
  (4) **Проверка по ФОРМЕ, без словарей (Конституция VII), по абзацу против текста первого прохода; любое срабатывание
  — откат к первому проходу:** изменилось мультимножество числовых токенов после одной нормализации (разделители
  тысяч, десятичный знак, диапазоны — та же, что у `_number_leak_tokens` 068; ловит и «23 → 32», «1.5 → 15», и запись
  числа словами — последнее принимается как консервативный откат); появилось слово НЕ целевого письма (латиницей при
  целевом русском), которого не было в первом проходе (ловит «will»; имена, ссылки и термины, бывшие латиницей в первом
  проходе, разрешены); появилось слово со смешанным алфавитом; изменился префикс нумерации пункта; потерян маркер
  сноски; отношение длин к первому проходу вне границ (границы выводятся в `plan.md` из распределения C до кода).
  Маркеры и число абзацев блока не совпали с первым проходом — откат всего блока.
  (5) **Отказ прохода не роняет блок:** ошибка, исчерпание попыток, пустой ответ, Stop пользователя — остаётся первый
  проход, WARNING; Stop завершает прогон как сейчас.
  (6) **Учёт один раз:** счётчики disposition (`record_*` генератора, `_generation.py:334`, `:1056`) записываются по
  ИТОГОВОМУ тексту блока один раз; у второго прохода — свои счётчики (отправлено, принято, откачено по причинам) и
  стадия бухгалтерии `literary_polish`; реестр абзацев и проекция аудиокниги получают итоговый текст.
  (7) **Артефакт откатов:** `<artifact_dir>/literary_polish_rollbacks.jsonl` (UI — в `.run/` по тем же правилам
  срока и числа, что `marker_attempts`): run ID, блок, абзац, модель прохода, причина, текст первого прохода, кандидат,
  итог; события `literary_polish_paragraph_rolled_back` уходят в `events.jsonl` и лог прогона (068 FR-002); полей
  в приёмочном отчёте — счётчики и путь артефакта. `docs/LOGGING_AND_ARTIFACT_RETENTION.md` описывает артефакт.
- **FR-005 Примечания в конце главы.** Обследование до правила на данных bake-off (входной промпт блока, роль и регион
  абзацев p0102–p0111 в задании, ответы A и Gemini, правило 12 / D1 063, ветка URL детектора `:76`): почему Gemini
  оставляет комментарии примечаний по-английски, а A переводит (и переводит имена авторов, которые должны оставаться).
  Приёмка — три независимых условия: (а) содержательные комментарии примечаний переведены; (б) библиографические
  данные сохранены по D1; (в) шлюз учитывает смешанное примечание по его непереведённой части, а не целиком. Обязателен
  отрицательный тест: настоящий непереведённый комментарий шлюз продолжает ловить. Наличие латиницы само по себе
  дефектом не считается; порог шлюза не ослабляется.
- **FR-006 Бюджеты вывода — безопасные лимиты, не цена.** Лимиты генерации отделены от коэффициентов оценки цены
  FR-007. Для модели задаётся множитель лимита относительно нынешней формулы (`max(len // 3 * 4, 512)`, потолок
  `_MODEL_OUTPUT_TOKEN_CEILING`); для текущей модели множитель 1 — бюджет `single`, `edit`, `audiobook` не меняется
  побайтно. Глоссарий сохраняет зависимость от числа запрашиваемых записей и служебного JSON
  (`glossary_max_output_tokens`, `text/glossary_pass.py:1469-1491`), множитель модели применяется к ней. Множители
  выводятся в `plan.md` из распределения ОТДЕЛЬНЫХ ответов bake-off (не агрегатов), с рассуждением и повторами, с
  запасом до p99; лестница деградации пересчитывает размер ступеней от того же лимита, потолок остаётся. Замер: вызов
  глоссария Haiku на Money гл. III возвращает полный список; обрывов `incomplete` на 3.7 `low` 0.
- **FR-007 Оценка цены — отдельный модуль, первая версия без самокалибровки.** `pipeline/cost_estimate.py` (имя — в
  `plan.md`): вход — подготовленный документ (символы источника по блокам, число блоков, размер системного промпта и
  контекста, число вызовов глоссария), языковая пара и эффективная конфигурация режима (FR-001); выход — оценка
  **текстовых стадий** (глоссарий + перевод + шлифовка), стадии картинок явно не входят и подписаны как «без
  картинок». Коэффициенты «токенов ввода/вывода на символ» — **фиксированная версионированная таблица** по (модель,
  стадия, языковая пара) с происхождением каждой цифры (прогон, дата). Цены — список моделей OpenRouter
  (`/api/v1/models`), кеш в `.run/` с датой; без сети — последний кеш с датой; без кеша — «цена неизвестна». Вилка:
  верхняя граница — прайс; нижняя — эмпирический сценарий скидки провайдера (21–24 % на полных книгах A — «скорее
  всего кеш промпта», для других моделей не проверено); причина проверяется по полям кеша в ответе (`cached_tokens`,
  `cache_write_tokens`, `cache_discount` OpenRouter), и пока не подтверждена — нижняя граница подписана как сценарий.
  `model_accounting` не получает оценочных цифр. **Снимок оценки** (режим, эффективные модели и уровни, версия
  коэффициентов, дата цен, оценка) сохраняется с результатом прогона (`build_result_bundle`
  `processing/processing_runtime.py:1684`); после прогона UI показывает факт рядом со СВОЕЙ оценкой из снимка;
  старый результат без снимка — без оценки. Событие `cost_estimate_vs_actual` — оценка, факт по тем же стадиям,
  относительная ошибка `(факт − оценка_верх) / факт` и попадание в вилку.
- **FR-008 Замер (платный, после кода).** Полный прогон Money и RM в обоих режимах через канонический раннер
  (≈ 5–6 $ — сумму подтверждает владелец перед запуском). Коэффициенты FR-007 замораживаются ДО прогонов. Слепое чтение —
  одним рецензентом в одном раунде на главу: новые тексты обоих режимов против замороженных якорей bake-off (C,
  G-low-cons, A) плюс контроль воспроизводимости — 10 абзацев повторены в выборке под другим кодом.

## Success Criteria *(mandatory)*

- **SC-001**: «Стандарт» на двух главах bake-off — в ОДНОМ раунде с якорем C: средние литературность и верность не
  ниже якоря больше, чем на разброс контрольных повторов этого раунда; подтверждённых смысловых регрессий (каждая
  прочитана) нет. Откаты шлифовки: опубликован знаменатель (абзацев отправлено), каждый откат прочитан; откаты
  хорошего абзаца ЗА ИСКЛЮЧЕНИЕМ записи числа словами (принята как консервативная) ≤ 10 % откатов.
- **SC-002**: «Качество» на двух главах — 0 токенов рассуждения, 0 обрывов `incomplete`; в одном раунде с якорем
  G-low-cons — то же правило, что в SC-001.
- **SC-003**: Money гл. III доставляется в обоих режимах; условия (а)–(в) FR-005 выполнены; отрицательный тест шлюза
  зелёный; порог шлюза прежний.
- **SC-004**: глоссарий прогона в обоих режимах — без обрезанных вызовов; число терминов в пределах ±15 % от текущей
  модели на тех же главах.
- **SC-005**: на полных книгах FR-008 с коэффициентами, замороженными до прогона, факт попадает в вилку оценки или
  относительная ошибка к её верхней границе ≤ 25 % — это проверяемая гипотеза; результат записывается как есть.
- **SC-006**: `edit` и `audiobook` побайтно не меняются (запросы, промпты, бюджеты); `single` повторяет нынешний
  перевод (тот же запрос без `reasoning`, те же бюджеты).
- **SC-007**: полный прогон тестов зелёный; приёмочное ревью Codex по всем затронутым поверхностям до слияния в `main`.

## Non-goals

- **Пакетный API (`:batch`, −50 %)** — не строится: он асинхронный (ответы через минуты–часы), интерактивному UI не
  подходит; вернуться можно отдельной спекой для фоновых прогонов.
- **Самокалибровка коэффициентов оценки цены** — не в первой версии (ревью Codex 2026-11-09: частичные и
  остановленные прогоны, повторное применение, конкурентная запись, смешение языков и уровней рассуждения); сначала
  фиксированная таблица и сравнение оценки с фактом в каждом прогоне; к калибровке возвращаемся по данным этих
  сравнений.
- **Возобновление наполовину оплаченного второго прохода** после перезапуска — не строится: перезапуск повторяет блок
  целиком.
- **Отклонённые конфигурации bake-off** — не возвращаются без нового замера: B (шлифовка той же flash-lite — не
  улучшает, ухудшает верность), D (Haiku одним проходом — не лучше A, заблокирован на Money), E (Sonnet — цена),
  3.8-flash (качество как у 3.7, дороже), `reasoning.effort = medium` (думает не меньше умолчания).
- Не выносить выбор модели режима, уровня рассуждения или интенсивности в интерфейс (D-3); не держать ручных
  поправок цены.
- Не трогать модели и промпты `edit`/`audiobook`, картинок, проверки границ, reader cleanup.
- Не вводить словари и литералы книг (Конституция VII): проверки отката FR-004 и правка FR-005 — по форме; словаря
  числительных нет — запись числа словами откатывается консервативно.
- Не менять шлюз качества ради прохождения (FR-005 — сначала механизм).

## Anti-regression

1. `single` = нынешний перевод: тот же запрос (без `reasoning`), тот же промпт, те же бюджеты (множитель FR-006 = 1).
2. Инварианты 063–068 на прогонах FR-008: числа, маркеры сносок, заголовки уровней 1–2, склейки ячеек, указатель
   (дубли/потери 0), события блока в `app.log` прогона.
3. Второй проход не проходит через импорт и не меняет структуру: число абзацев, роли, уровни заголовков, маркеры —
   как у первого прохода; несоответствие → откат блока, не падение; учёт disposition — один раз.
4. `model_accounting` не получает ни одной оценочной цифры; факт и оценка — в разных полях и событиях.
5. Канонические пути (AGENTS.md): тесты — `scripts/test.sh` через WSL, прогоны — `scripts/run-real-document-validation.sh`;
   `.run/` и `.env` вне git; полный прогон в главном дереве и пустой `git status --porcelain` перед «зелёным».

## Assumptions

- Цены OpenRouter на 2026-11-09 (вход / выход за 1 млн): gemini-3.1-flash-lite-preview 0,25 / 1,50, claude-haiku-5.5
  0,10 / 0,50, gemini-3.7-flash 0,75 / 3,75. Оценки «книга ≈ …» в D-1 — экстраполяция с двух глав двумя способами
  (63, Changelog), не замер; FR-008 их проверяет.
- Слепое чтение воспроизводится плохо между раундами (см. «Что измерено»); выводы опираются только на сравнения внутри
  одного раунда.
- `reasoning.effort = low` у gemini-3.7-flash сейчас даёт 0 токенов рассуждения; если провайдер изменит поведение,
  бухгалтерия FR-003 это покажет.
