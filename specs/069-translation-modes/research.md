**Шлюз** (`fr005_gate_replay.out`; повтор текущего правила на `delivered.md` совпал с

строка p0110 + p0111 (1 344 — библиография плюс переведённый комментарий). Не засчитан p0103, где комментарий

Шлюз штрафует правильное поведение и пропускает неправильное.

**Правка по форме (WP-5), три независимых условия:**
- (в) шлюз: для доставленного абзаца, который по форме — цепочка примечаний (`notes_run_parts`), засчитывается
  только **непереведённая часть** — ведущий текст и записи, у которых доля латиницы ≥ 0,8 (тот же тест, что у
  абзаца) и которые НЕ ссылка по per-entry-тесту 067; к этой части применяются те же пороги (280 символов,
  30 слов на образец; 2 000 символов и 2 % на документ). Повтор на всех прогонах: Gemini-варианты Money 1 993–2 036 →
  **346–348**; A/B/C 0 → 346 (остаток — список фирм примечания 38: имена, ниже всех порогов); **D (Haiku оставил по-
  английски определения МВФ) 6 689 → 3 656 — по-прежнему выше 2 000 и 2 %, доставка по-прежнему блокируется**
  (естественный отрицательный случай); все RM — 0 → 0. Порог не меняется; ветка URL для обычных абзацев не
  трогается;
- (а), (б) запрос: раздел аппарата блока называет, в каких примечаниях абзаца есть авторский текст по форме
  («в абзаце [[DOCX_PARA_p0103]] авторский текст есть в примечаниях 3, 6»), и правило говорит решать по каждому
  примечанию, а имена авторов считать частью ссылки. Проверка (а)/(б) — только прогоном (FR-008, SC-003);
  детерминированно проверяется, что раздел называет ровно записи-не-ссылки и ничего — у абзаца из одних ссылок.

**Отклонённая альтернатива для (б):** детерминированно возвращать записи-ссылки из источника поверх ответа модели.
Гарантирует (б) для любой модели, но переписывает ответ правилом формы без замеренной доли ложных возвратов
(«See for instance» / «Source:» вернулись бы английскими); вернуться, если FR-008 покажет нарушение (б).

## R5. Решения по архитектуре (кратко; подробно — plan.md)

| Вопрос | Решение | Альтернативы и почему нет |
|---|---|---|
| Как параметры прохода доходят до вызова | явный `GenerationRequestProfile` (рассуждение, множитель, стадия учёта) — ключевой аргумент `generate_markdown_block` / `request_text_completion`, протаскивается внутри `_generation.py` в повторы, восстановление и лестницу; передаётся только когда задан | ContextVar (как у `model_accounting`) — скрытое состояние в генераторе, который весь в одном файле; новый аргумент в каждом вызывающем — двойники тестов |
| Однократный учёт счётчиков второго прохода | `model_accounting.pass_counter_scope("literary_polish")` — счётчики генератора (disposition, повторы, путь API, удаления текста) внутри области идут в раздел второго прохода, не в первый | флаг профиля «не записывать» — `record_text_removal` вызывается в `output_validation`, флаг туда не доходит |
| Где встаёт второй проход | `process_single_block` после `classify_processed_block_fn` == `valid` и до `model_kept_apparatus` (`block_execution.py:2283-2288`) | внутри `generate_markdown_block` — генератор не знает статусов политики и аппарата; после реестра — реестр и проекция аудиокниги увидели бы первый проход |
| Контекст второго прохода | до — хвост доставленного текста предыдущего блока (целевой язык), после — пусто | исходный английский контекст — повод «перевести ещё раз» и смешение языков в проверке утечки контекста |
| Множители лимита | таблица в коде `generation/output_budget.py` (модель → множитель с происхождением) | ключ конфига — ручка, которую владелец запретил (правило «никаких ручек») |
| Таблица коэффициентов цены | `resources/cost_estimate_coefficients.json`, версия + происхождение каждой цифры | Python-константы — тот же эффект, но таблицу удобнее заморозить и сравнить в отчёте по версии |
| Прайс | `pipeline/price_list.py`: `/api/v1/models` OpenRouter, кеш `.run/price_list/openrouter_models.json` с датой, тайм-аут 5 с, свежесть 24 ч | запрос при каждом рендере — блокирует UI; вшитые цены — устаревают молча |
