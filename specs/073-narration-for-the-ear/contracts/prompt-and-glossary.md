## 2. Секция словаря в системном промпте блока (FR-004; research R6)

Добавляется к уже полученному базовому промпту (основному и исправления) через `_combine_system_prompt_with_block_focus`
(`pipeline/block_execution.py:1202-1209`) — после всех частей, через пустую строку:

```text
КАК ЧИТАТЬ СОКРАЩЕНИЯ ЭТОЙ КНИГИ (каждое сокращение из списка читайте ровно так; если чтение — слово, склоняйте его по смыслу):
- <написание> -> <чтение>
- ...
```

- Заголовок — константа `READING_GLOSSARY_SECTION_HEADER` (литерал выше, одна строка); строки — `_render_glossary_line`
  (`document/segments.py:97-118`): `- source -> target`, без `(имя)`, `≠`, `—` (поля `kind="term"`, `note=""`).
- Только записи, чей кандидат встречается в исходнике озвучиваемых абзацев ЭТОГО блока (точное написание), в порядке
  первого появления в блоке; бюджет 2 000 знаков (`render_glossary_prompt_section`, `- ...` при обрезке).
- Нет записей → секции нет, промпт блока побайтно как без словаря.
- Основной запрос и исправление одного блока получают ОДНУ и ту же строку секции (одна функция на одних входах).

## 3. Шаг словаря чтения: пакеты и повторы (FR-004; research R5, R7)

Системная инструкция — новый файл `resources/prompts/audiobook_reading_glossary.txt` (просит: для каждого сокращения —
как диктор произносит его в русской речи, кириллицей; знак U+0301, где ударение неочевидно; без цифр и латиницы; если
расшифровка общепринята и так читается — можно словами; ничего, кроме JSON).

Запрос одного пакета (≤ 40 кандидатов) — `_request_envelope(model, instructions, payload,
max_output_tokens=glossary_max_output_tokens(len(batch)))` (`text/glossary_pass.py:1458-1470`, `:1492-1507`; 40 → 4 096);
`payload`:

```json
{"candidates": [{"abbreviation": "ABC", "occurrences": 12, "context": "…до 160 знаков вокруг первого вхождения…"}]}
```

Ответ:

```json
{"readings": [{"abbreviation": "ABC", "reading": "…"}]}
```

Разбор — `data-model.md` §4 (`parse_reading_glossary_response`). Клиент — тот же, что у вызова блока
(`initialization.text_client or initialization.client`), стадия `audiobook_reading_glossary`, `should_stop` передаётся.

| Ситуация | Поведение (политика вызова блока, `generation/_generation.py:3541-3606`) |
|---|---|
| ответ разборчив | пакет принят; ровно один вызов |
| повторяемая ошибка транспорта (`is_retryable_error`), незавершённый ответ, неразборчивый ответ (нет JSON / нет `readings`) | повтор этого пакета, до `context.max_retries` попыток, пауза `retry_backoff_seconds(n)` = `min(2 ** (n − 1), 8)` с; обрезанный ответ — бюджет растёт `_boost_request_output_budget` |
| неповторяемая ошибка или попытки исчерпаны | `ReadingGlossaryUnavailable` → прогон «ошибка» тем же путём, что неисправимый вызов блока (research R7) |
| кандидаты пакета без принятого чтения (не отвечены / отклонены формой) | после первого прохода — один повторный запрос их пакетами по 40 (те же правила); после него — `unresolved`, WARNING, шаг успешен |
| Stop | перед шагом и перед каждым пакетом; во время вызова — `LatePhaseStopped` → `stopped` |

Счёт вызовов (SC-007): первый проход — `ceil(sent / 40)` вызовов при разборчивых ответах; + повторы сбойных пакетов; +
`ceil(без чтения / 40)` повторного запроса. Обычное исключение, не признанное повторяемым, не повторяется.

## 4. Паузы — не в тексте (FR-007, решение D-4)

Меток `<#x#>` в тексте озвучки нет: решение владельца D-4 заменило `.tts.minimax.txt` файлом книги
`.narration.json`, где вид паузы — данные сегмента (`pause_after`, `contracts/narration-book.md` §6.1), а тишину
вставляет инструмент озвучки при сборке. Промпт режима по-прежнему запрещает модели любые теги и пометки
(`resources/prompts/operation_audiobook.txt`, последняя строка).
