## R1. Знак ударения и лексические сравнения: один помощник (FR-002, SC-005)

**Живость дефекта (Конституция VIII, `stress_mark_liveness.py`, debug-only).** На `7347bd3`, синтетическая фраза из
восьми слов, тот же текст с U+0301 в семи словах:

| Сравнение | Без знака | Со знаком |
|---|---|---|
| `paragraph_coverage` (`text/narration_coverage.py:48-55`) | 5 из 5, `ratio=1.0` | 2 из 5, `ratio=0.4` → ложное `low_coverage` (порог 0,6, `:28`) |
| `roman_numerals` (`text/narration_residue.py:68`, `:142`) | `глава IV` → класс найден | `глава ÍV` → класса нет |
| `_detect_context_leakage` (`generation/_generation.py:1466-1500`) | протечка найдена | `None` — протечка пропущена |
| `all_caps` (`text/narration_residue.py:122-130`) | `АЛМАЗНЫЙ ВЕТЕР` → найден | со знаком в середине длинных слов — найден; форма Codex `А́ЛМАЗ ВЕ́ТЕР` (знак после первой буквы) теряет второе длинное слово — пропуск по построению (`_LETTER_RUN`, `:67`) |

**Решение.** Новый модуль-лист `text/narration_forms.py` (импортирует только `re`/`unicodedata`; `text/__init__.py` пуст,
цикла нет):

- `without_combining_marks(text) -> str` — перенос дословно `_without_combining_marks`
  (`document/narration_exclusion.py:93-96`); там остаётся импорт под прежним именем (вызов `:109`).
- `without_combining_marks_with_offsets(text) -> tuple[str, tuple[int, ...]]` — та же строка и для каждого её символа
  индекс в исходной; конец совпадения в исходной строке = индекс последнего символа + 1, продлённый через следующие
  знаки M* (знак принадлежит своей букве).
- `letter_series(text, *, digits_inside=False) -> list[LetterSeries]` — правило единицы FR-003/FR-004 (R2, R4): серия
  букв (L*) вместе с их знаками (M*), дефисами (`-`, U+2010, U+2011) и апострофами (`'`, U+2019), с цифрами Nd внутри при
  `digits_inside`; дефисы и апострофы по краям отрезаются; серия без буквы не единица. Позиции — исходной строки.

Применение (все — ЛЕКСИЧЕСКИЕ сравнения): покрытие — обе стороны через `without_combining_marks` до `_LETTER_RUN`;
`all_caps` и `roman_numerals` — поиск по строке без знаков, позиция образца переводится в исходную через смещения
(образец `_sample` режет исходную строку, `:104-106`); обрывок — как сейчас, через общий помощник; протечка —
`_normalize_leakage_comparison_text` (`:1462-1463`) снимает знаки, `_detect_context_leakage` итерирует токены
`_WORD_TOKEN_PATTERN` (`:78`) по строке без знаков и вырезает фрагмент из ИСХОДНОГО ответа по смещениям — его потом
ищет подстрокой `_trim_boundary_context_leakage` (`:1506-1528`), поэтому фрагмент обязан быть срезом исходной строки.

Не трогаются: точная сборка по ID и текстам (`pipeline/narration_postprocess.py:188-215`) — побайтная, видит потерю
знака (Anti-regression 5); правило склейки (`:127-140`) — знак не меняет начало/конец абзаца (Codex 7); чистка
(`text/narration_cleanup.py:280` — только So/Sm); классы `digits`, `symbols`, `url_or_domain`, `tag_form` — их формы
знак не задевает (знак не цифра и не символ).

**Почему.** FR-002 требует ОДИН помощник; смещения нужны ровно там, где сравнение отдаёт адрес (образец остатка,
фрагмент протечки). Модуль в `text/` — ниже `document/` и `generation/` по употреблению, без обратных импортов.

**Отвергнуто.**
- **NFC-нормализация.** У кириллицы с U+0301 нет составных символов — строка не меняется.
- **Добавить M* в классы регулярных выражений.** `re` не знает `\p{M}`; перечисление диапазонов знаков — список
  (Конституция VII) и тихо устаревает с версией Unicode.
- **Снимать знак в чистке озвучки.** Уничтожает саму функцию (FR-001).

## R2. Класс остатка `latin` (FR-003, SC-001)

**Решение.** `text/narration_residue.py`: `RESIDUE_LATIN = "latin"` — в `RESIDUE_CLASSES` после `tag_form` (исправимые
идут подряд, отчёт сохраняет фиксированный порядок, `tests/test_narration_residue.py:123`), в
`REPAIRABLE_RESIDUE_CLASSES` (`:50-59`). Единица — `letter_series(текст, digits_inside=False)` (R1), в которой хотя бы
одна буква с `LATIN` в `unicodedata.name` (то же свойство, что `text/glossary_pass.py:1890-1891`). Исключения, обе по
форме: (1) серия внутри совпадения `_URL_OR_DOMAIN` (`:73-77`) — его спан заменяется пробелами той же длины до разбора,
поэтому позиции не съезжают; (2) серия, целиком совпадающая с формой класса `roman_numerals` (две и больше букв
`[IVXLCDM]` или символы Nl, `:68`, `:100-101`). Одиночные `I`, `V`, `X` — латиница (класс `roman_numerals` их тоже не
видит; исправление их напишет словами — для слуха это верно). `count` — число единиц, как у остальных классов
(докстринг `:7-10`). Химические формулы и единицы (`H₂O`, `kg`) — латиница (граница спеки).

**Замер** (`measure_073.json`, `baseline_chapters.py`):

| Вход | единиц `latin` в исходнике озвучиваемых абзацев (различных; абзацев) | осталось в `.tts.txt` базы (абзацев) |
|---|---|---|
| RM гл. 3 | 5 (5; 3) | 0 |
| Money гл. 3 | 44 (34; 20) | 2 (2) — `Юромaни`: кириллица с латинской «a» внутри |

Сегодняшний проход уже раскрывает большинство латинских сокращений (правило 2 промпта), остаток — названия и цитаты.
Смешанное слово с латинской буквой-двойником (`Юромaни`) класс тоже ловит — это верно: TTS прочитает «a» латиницей.

**Следствие для SC-001 (дефект спеки, исправлен).** «Знаменатель — единиц до исправления — не равен нулю на трёх
входах» неисполнимо: на RM база уже 0, а новое правило промпта снизит «до исправления» дальше. Знаменатель — единицы
`latin` в ИСХОДНИКЕ озвучиваемых абзацев (5 / 44 / 528, непуст на всех трёх); «до исправления» публикуется, но может
быть 0. В событие — новое поле `latin_source_unit_count` (FR-010; R11).

**Отвергнуто.** Латиница как НЕисправимый класс (только отчёт) — противоречит SC-001; транслитерация кодом — словарь
транслитерации (VII, Non-goals спеки).

## R3. Правила промпта: ударения, латиница, номера разделов (FR-001, FR-003, FR-005)

**Решение.** `resources/prompts/operation_audiobook.txt` (сейчас правила 1–7, `:4-10`) получает правила с явным
приоритетом (Codex 6):

- **Ударение (FR-001).** Знак U+0301 сразу после ударной гласной — только в слове, которое пишется так же, как другое
  слово с другим ударением, когда ударение ясно из контекста; в остальных словах знака нет; заглавная гласная, «+»,
  апостроф, транскрипция — запрещены. Пример в самом правиле — одна пара омографа со знаком (U+0301 в тексте промпта).
- **Латиница (FR-003).** Слова латиницей — кириллицей, как их произносят по-русски (имена, названия, термины, цитаты).
  Приоритет записан в промпте списком: (1) сокращение из раздела «Как читать сокращения этой книги» — ровно как там,
  склоняя по контексту, если это слово; (2) латинское сокращение без записи — названиями букв по-русски; (3) латинский
  инициал — названием буквы по-русски, полное имя не выдумывается (правило инициалов 070 — `:5` — сохраняется);
  (4) «аббревиатуры оставляйте как есть» (`:8`) относится только к кириллическим сокращениям без записи.
- **Номер раздела (FR-005).** Заголовок (строка с `#`; источник видит модель — исходник с префиксом идёт в запрос,
  `pipeline/audiobook_plan.py:97-113`), начинающийся с числа или римского числа с точкой, — порядковое числительное
  среднего рода с точкой («Первое.», «Четвёртое.»); слов «глава», «раздел» не добавлять, если их нет в исходнике.

`operation_audiobook_repair.txt` (`:1`): к перечню остатка — «слова латиницей — кириллицей по тем же правилам»; то же
правило раздела сокращений; оговорка «аббревиатуры как есть» сужается до кириллических. `example_audiobook.txt` — одна
из 3–4 пар (ограничение `tests/test_audiobook_prompt.py:117-120`) получает латинское название и омограф со знаком в
результате; гард `:131-139` (нет цифр, знаков, слов ≥ 4 заглавных, скобок в результате) по-прежнему зелёный.

**Замер базы FR-005** (`baseline_forms.json`): на полной Money 36 заголовков (все уровня 2) начинаются с «N.»; в
`.tts.txt` базы — пять форм: количественное («Два.», «Три.», «Пять.») 19, «Первое.»-тип 7, «Вторая глава.» 5, «Глава
третья.» 4, «Четвертая.» 1 — то есть в 9 из 36 модель ДОБАВЛЯЕТ слово «глава». Money гл. 3 — 5 таких заголовков, RM гл. 3
— 0 (SC-003 на RM неприменим, на Money гл. 3 и полной — непустой набор). Римских номеров в начале заголовков на корпусе
нет (все 36 — арабские); правило их называет — по форме.

**Почему.** Конфликт правил 2/5 с транслитерацией (Codex 6) снимается приоритетом в самом тексте, а не порядком
строк. Правило номера — одно на все заголовки, без словаря чисел (VII).

**Отвергнуто.** Номер разделов через словарь чтения (Codex 4: ключ записи не представим, `text/glossary_pass.py:337`,
`:2128`); детерминированная замена «N.» кодом — словарь числительных и разбор падежей (VII).

## R4. Кандидаты словаря чтения: форма, предел (FR-004)

**Дефект спеки (исправлен).** «Все буквы которых заглавные … `CoR-EU`» — противоречие: в `CoR-EU` строчная «o».
Замер двух форм на корпусе (`measure_073.json`):

| Вход | «все заглавные» | «≥ 2 заглавных и заглавных больше строчных» | разница |
|---|---|---|---|
| RM гл. 3 | 4 различных / 8 вхождений | 4 / 8 | — |
| Money гл. 3 | 17 / 79 | 17 / 79 | — |
| Money полная | 67 / 417 | **68 / 422** | ровно `CoR-EU` (5 вхождений) |

**Решение.** Кандидат — единица `letter_series(текст, digits_inside=True)` (R1) озвучиваемого абзаца исходника, у
которой не меньше двух заглавных букв и заглавных больше, чем строчных; не кандидат: единица, целиком римское число
(форма класса `roman_numerals`), единица внутри адреса сайта (маска R2), любая единица абзаца, который целиком
набран заглавными (форма класса `all_caps`, `text/narration_residue.py:122-130`; на полной Money таких абзацев 3).
Цифры внутри — только Nd: надстрочный номер сноски (`ОЭСР⁷`) — не часть единицы. Совпадение — точное написание.
Предел `READING_GLOSSARY_MAX_CANDIDATES = 200`: в три раза больше полной Money; при превышении — самые частые
(равенство — по первому появлению), число отброшенных — в событии, их написания — в артефакте.

Распределение на полной Money: 40 из 68 встречаются один раз; 25 самых частых дают 89 % вхождений; первые 10 —
`TRC` 123, `США` 69, `ВВП` 32, `ЭКО` 29, `ЕС` 15, `МВФ` 12, `НПО` 12, `МСП` 10, `ГЛАВА` 9, `БМР` 9. Латинских — 26,
кириллических — 42. Среди кандидатов есть слова заглавными внутри обычного абзаца (`ГЛАВА`, фамилии строки
библиографии в теле) — принятый край (D-3): чтение для них — слово обычным регистром, вреда нет.

По блокам: записи нужны 95 из 283 блоков полной Money, до 7 на блок, в среднем 2,0 (всего 190 записей по блокам);
Money гл. 3 — 10 из 22, до 5; RM гл. 3 — 3 из 11, до 3.

**Отвергнуто.** `extract_glossary_candidates` перевода (`text/glossary_pass.py:498-502`) — серии слов с заглавной и
ранжирование семей: 842 различных написания на полной Money (Codex), и форма другая (имена, не сокращения).
Единица «только `[A-ZА-Я]{2,}`» — список письменностей (VII).

## R5. Вызов словаря чтения: один на книгу (FR-004, SC-007)

**Решение.** Новый модуль `pipeline/reading_glossary.py`, функция `run_reading_glossary(*, paragraphs, client, model_id,
should_stop, log_event, filename, artifact_context, request_text_completion_fn=request_text_completion,
write_artifact_fn=_write_run_glossary_artifact) -> ReadingGlossary`. Части 063 переиспользуются, фаза перевода
(`pipeline/glossary_phase.py:198-231`) не вызывается:

| Нужда | Что берётся | Откуда |
|---|---|---|
| ровно одна попытка HTTP | `_single_attempt_client` (`with_options(max_retries=0)`) | `pipeline/audiobook_repair.py:78-90` |
| вызов и учёт стадии | `request_text_completion(..., usage_stage=STAGE_AUDIOBOOK_READING_GLOSSARY, should_stop=...)` | `generation/_generation.py:2276-2315` |
| форма запроса | `_request_envelope(model, instructions, payload, max_output_tokens)` | `text/glossary_pass.py:1458-1470` |
| бюджет ответа | `glossary_max_output_tokens(n)` (68 кандидатов → 6 784; 200 → потолок 16 384) | `text/glossary_pass.py:1492-1507` |
| разбор JSON | `_load_json_object` (коды `empty_response`, `no_json`, `invalid_json`) | `text/glossary_pass.py:2072-2089` |
| строки секции | `render_glossary_prompt_section(terms, header=..., max_chars=...)` с `GlossaryTerm(source_term, target_term)` → `- TRC -> …` | `document/segments.py:77-91`, `:97-121` |
| артефакт прогона | `_write_run_glossary_artifact(payload, context=)` → `.run/run_glossaries/<run>_<ms>.json`, та же чистка | `pipeline/glossary_phase.py:172-191`, `core/constants.py:56` |
| цена вызова | `_stage_usage(stage=...)` — получает необязательный параметр стадии, по умолчанию прежняя | `pipeline/glossary_phase.py:147-161` |

Стадия — новая константа `STAGE_AUDIOBOOK_READING_GLOSSARY = "audiobook_reading_glossary"` в
`core/model_accounting.py:81-90` (закрытого реестра стадий нет — `record_model_call_usage` принимает любую строку).
Запрос — JSON `{"candidates": [{"abbreviation", "occurrences", "context"}]}`, контекст — до 160 знаков вокруг первого
вхождения (смысл сокращения часто раскрыт рядом). Ответ — `{"readings": [{"abbreviation", "reading"}]}`; свой разбор
(закрытый словарь отказов, `data-model.md` §4): `not_a_candidate` (написание не совпало побайтно с отправленным),
`empty_reading`, `latin_in_reading`, `digit_in_reading`, `duplicate` (первое побеждает). Частичный ответ — принятые
записи используются. Стоп ДО вызова → статус `stopped`, вызова нет; во время — `request_text_completion` с
`should_stop` поднимает `LatePhaseStopped` → `stopped`. Пустой список кандидатов → `no_candidates`, вызова нет. Любое
исключение → `failed` + WARNING `audiobook_reading_glossary_failed`, книга идёт без словаря (Anti-regression 2).

**Почему.** Политика одного вызова у озвучки уже есть (исправление, спека 070) — её и берём; механизм 063 с пятью
вызовами (`pipeline/glossary_phase.py:90`, `:802-893`) — нет. Своя строка разбора проще, чем подгонка к
`parse_glossary_response` (`text/glossary_pass.py:2092-2160`): тот требует `GlossaryCandidate`, сравнивает по ключу
`normalize_glossary_key` (`:337-340` — нижний регистр, буквенные токены: `EA-16` и `EA` совпали бы) и навязывает виды
`term`/`name`.

**Отвергнуто.** Вызов фазы 063 с флагом «один вызов» — меняет модуль перевода (Non-goals); копия
`_write_run_glossary_artifact`/`_stage_usage` — дубль (правило владельца: переиспользовать). Параметр стадии у

## R6. Доставка секции в блок: основной запрос и исправление (FR-004, SC-007)

**Замер** (`measure_073.json`, `debug_seps.py`): исключённых с причиной `fragment` абзацев, чей исходник непуст и без

**Дефект спеки (уточнён).** FR-006 ссылается на `document/narration_exclusion.py:161-167` — это ветвь исключённых из
правила обрывка ролей (заголовок и др.); абзац тела `***` исключает общее правило обрывка (`:168-169`) с той же
причиной `fragment`. Сигнал определяется по ФОРМЕ исходника исключённого абзаца, а не по ветви правила.

**Решение.**
1. `document/narration_exclusion.py`: выражение `not any(character.isalnum() ...)` (`:167`) становится публичной
   функцией `has_no_letter_or_digit(text) -> bool` и вызывается оттуда же; форма разделителя —
   `is_scene_break_text(text)`: непустой после `strip()` и `has_no_letter_or_digit`.

   порядку, включая блоки-пропуски, `pipeline/block_execution.py:2335`; блоки идут последовательно, `:2614`) дописывает
   в `state.narration_paragraph_kinds` пары `(paragraph_id, kind)`, `kind` ∈ `narrated` / `scene_break` (исключён с
   причиной `fragment` и `is_scene_break_text(исходник)`) / `excluded` — в порядке абзацев блока.
3. `pipeline/narration_postprocess.py`: чистая `scene_break_before_ids(kinds, *, present_ids) -> frozenset[str]` —
   проход по порядку: `scene_break` взводит флаг, если до него был озвучиваемый абзац; первый следующий `narrated`,
   чей ID есть в `present_ids`, получает отметку и гасит флаг; `excluded` и отсутствующие `narrated` прозрачны;
   невзведённый флаг в конце книги отметки не даёт. Несколько разделителей подряд — одна отметка.
4. `assemble_narration_records(records, expected_paragraph_ids=None, scene_break_before_ids=frozenset())`

**Почему.** Исключённые абзацы в записи не попадают (`pipeline/audiobook_pass.py:195`, `:243-273`), поэтому позиция
разделителя сохраняется там, где ещё виден весь порядок абзацев, — при регистрации блока. Последовательность видов
переживает границы блоков (разделитель последним абзацем одного блока, текст — первым в следующем). Правило вычисления
— чистая функция, его краевые случаи SC-006 проверяются без конвейера.

**Отвергнуто.**
- **Арифметика ID** (`p0596` между `p0595` и `p0597`, `document/extraction.py:1163`) — предполагает, что порядок ID
