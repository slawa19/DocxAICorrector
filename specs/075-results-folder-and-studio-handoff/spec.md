## Решения владельца (2026-11-12)

1. «Файл json должен быть где-то доступен для скачивания, ссылка на него должна показываться в проекте перевода и
   сохраняться в доступном месте». Кнопка скачивания уже есть (`ui/_ui.py:1166-1176`); не хватает постоянного места.
   Сейчас группа результата пишется только в `.run/ui_results/` (`runtime/artifacts.py:366-471`), а этот каталог
   чистится сам: старше 7 суток или сверх 80 групп (`runtime/artifact_retention.py:60-61`). Это кэш, а не место
   хранения.
2. «Рядом с исходником» невозможно: файл приходит из браузера (`ui/_app.py:1085`, `st.file_uploader`), и папку, из
   которой его выбрали, браузер не сообщает. Владелец выбрал: **своя папка результатов, задаётся в `.env`, по
   умолчанию `<корень проекта>/translations`, каталог в `.gitignore`.** Папки на рабочем столе и в `D:\` создавались
   для удобства тестирования и в программу не закладываются.
3. «Делай» на предложение кнопки «Открыть в студии»: файл книги отправляется в запущенную студию одним нажатием,
   без ручного «Открыть новую книгу…».

## Requirements *(mandatory)*

### FR-001 — настройка папки результатов

Новая настройка — путь к папке результатов. Имя и место умолчания — по соглашению `core/config.py` и
`resources/config.toml` (префикс как у соседних настроек каталогов). Умолчание — `<корень проекта>/translations`;
относительный путь считается от корня проекта. В `.env.example` — закомментированная строка с объяснением.
`translations/` — в `.gitignore`.

### FR-002 — публикация результата в папку

После того как группа результата записана и проверена (`pipeline/late_phases.py:1505-1514`, событие
`ui_result_artifacts_saved`), файлы, которые экран результата предлагает скачать, копируются в
`<папка результатов>/<основа имени исходника>/` под **теми же именами, что дают кнопки скачивания**
(`ui/_ui.py:84-106`: `<stem>_edited.docx`, `<stem>.tts.txt`, `<stem>.tts.docx`, `<stem>.tts.pdf`,
`<stem>.narration.json`). Копируется только то, что построено; Markdown «для проверки», `meta`, `manifest` и отчёт
оформления не копируются (они остаются в `.run/ui_results/`).

- Повторный прогон той же книги **заменяет** файлы с теми же именами: в папке — последний результат. История
  остаётся в `.run/ui_results/` на срок его хранения.
- Файл с тем же содержимым не переписывается.
- Файл, который нельзя заменить (открыт в Word или проигрывателе; в WSL это `PermissionError`/`OSError` при
  записи поверх), пишется рядом как `<имя> (новая).<ext>` — так же решено в студии (`api_audio.copy_out`). Запись
  не должна падать из-за открытого файла.
- **Заблокированный результат (`delivery_status == "blocked"`) не публикуется**: экран называет такие файлы
  диагностикой, а папка результатов — место готового.
- Публикация — вторичная запись после доставки, по правилу Round-12 F1 (`pipeline/late_phases.py`, комментарий
  после `ui_result_artifacts_saved`): её исключение ловится и логируется, результат на экране не прячется.
- Событие `ui_results_published` (INFO) с `folder` и `paths`; при ошибке — `ui_results_publish_failed` (WARNING).
  Новые поля и события вписываются в `docs/LOGGING_AND_ARTIFACT_RETENTION.md`.
- Путь папки книги кладётся туда же, где экран берёт данные результата (session state рядом с
  `narration_exports` / артефактами), чтобы FR-003 его показал.

### FR-003 — путь и «Открыть папку» на экране результата

Под кнопками скачивания — строка «Сохранено в папку: `<путь>`» в Windows-виде (`/mnt/<буква>/…` → `<БУКВА>:\…`;
иначе путь как есть) и кнопка «Открыть папку». Кнопка открывает Проводник (`explorer.exe <windows-путь>` из WSL);
путь показан текстом в любом случае, поэтому его можно скопировать. Для всех режимов (правка, перевод, аудиокнига),
не только для озвучки. Если публикации не было (блокировка, ошибка) — строки нет.

### FR-004 — «Открыть в студии»

В ряду озвучки, рядом с «Файл книги для озвучки (.json)», — кнопка «Открыть в студии» (только когда файл книги
построен и результат не заблокирован).

- Нажатие отправляет байты `.narration.json` на `<адрес студии>/api/books` (`POST`, тело — файл как есть; так же
  делает страница студии). Адрес — новая настройка, умолчание `http://127.0.0.1:8601`.
- Если студия не отвечает (соединение отклонено), DocxAICorrector **запускает её сам**:
  `bash <папка студии>/scripts/studio.sh start` (скрипт ждёт готовности до 30 с и сам пишет причину неудачи), затем
  повторяет отправку один раз. Папка студии — новая настройка, умолчание `<родитель корня проекта>/AudiobookStudio`.
- Успех: студия возвращает `{"book_id": …}`; экран показывает ссылку «Открыть книгу в студии» на
  `<адрес студии в браузере>/#book=<book_id>` (в браузере — `localhost`, его же открывает `start-studio.cmd`
  студии). Повторная отправка той же книги обновляет ту же книгу в студии: `book_id` — хэш `book.source_token`
  (студия: `library.py:15-16, 39-54`), состояние и готовые дубли сохраняются.
- Ошибки, которые нельзя обойти, показываются текстом с причиной: нет папки студии (назвать настройку), скрипт
  запуска завершился с ошибкой (его вывод), студия ответила 4xx (её `detail`). Это ошибки конфигурации, а не
  деградированная ветка.
- HTTP-клиент — стандартный `urllib.request`: `httpx` в проекте есть только транзитивно (через SDK провайдеров,
  в `requirements.txt` его нет), а новая прямая зависимость ради одного запроса не нужна. Таймауты явные.
- События `studio_handoff_succeeded` / `studio_handoff_failed` с `book_id` / причиной.

### FR-005 — тексты интерфейса

Все новые строки — в обоих каталогах локалей (`ui/locales/*.json`); гард каталога (`tests/test_ui_i18n.py`) должен
их видеть.

## Success Criteria *(mandatory)*

- **SC-001**: тест на `write`-уровне: после доставки в `tmp`-папке результатов лежат ровно построенные файлы под
  именами кнопок; заблокированный результат — не публикуется; повтор с тем же содержимым — файл не переписан;
  «занятый» файл (симуляция `PermissionError`) — появился `(новая)`, исключения наружу нет.
- **SC-002**: перевод пути `/mnt/d/a/b` → `D:\a\b`, другой путь — как есть.
- **SC-003**: «Открыть в студии» с подменённым HTTP: успех → ссылка с `#book=<id>`; отказ соединения → вызван запуск
  студии и повтор; 400 → показан `detail`; нет папки студии → сообщение с именем настройки. Сети в тестах нет.
- **SC-004**: полный прогон `bash scripts/test.sh tests/ -q` зелёный в главном дереве, `git status --porcelain` пуст.
- **SC-005** (ручная, без денег): реальная студия в режиме `STUDIO_FAKE_TTS=1` принимает файл книги из готового
  прогона через тот же код отправки, ссылка открывает книгу.

## Non-goals

- Сохранять «рядом с исходником» — браузер не сообщает папку исходника (решение 2).
- Версии результатов в папке (даты, режимы в имени): в папке — последний результат; история — в `.run/ui_results/`.
- Публиковать результаты консольного прогона (`scripts/run-real-document-validation.sh`): у него свои каталоги
  прогонов.
- Отправлять книгу в студию без нажатия, или студии следить за папкой результатов.
- Менять схему `.narration.json` или API студии `POST /api/books`.
- Студии принимать DOCX: разобрано с владельцем 2026-11-12 — DOCX теряет паузы, выбранный уровень глав, словарь
  чтения и номера исходных абзацев, а разбор DOCX в студии продублировал бы разметку DocxAICorrector.

## Anti-regression

- Кнопки скачивания, их подписи и имена файлов не меняются (`tests/test_spec_072_result_screen.py`,
  `tests/test_spec_073_result_screen.py`).
- Группа в `.run/ui_results/` и её хранение не меняются (`tests/test_spec_073_result_group.py`, тесты retention).
- Ошибка публикации или отправки не прячет доставленный результат (Round-12 F1).
- **Тесты не пишут в `<корень проекта>/translations`**: папка результатов в тестах подменяется на `tmp_path`
  (фикстура в `conftest.py`), иначе каждый прогон тестов засорял бы папку владельца. Отдельный тест проверяет,
  что после прогона набора каталог не создан тестами (или фикстура autouse — тогда это проверяется ею).
- WSL runtime, канонические команды, LF — по `AGENTS.md`.
