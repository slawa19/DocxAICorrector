## Разбор двух расхождений

**Ложное падение (rethinking_money).** Блок 140 из 305, `target_chars=2`. Повторная
подготовка документа без единого вызова модели воспроизводит прогон точно (2265 абзацев,
305 заданий) и показывает, что это абзац `p0812` с текстом `2b` — номер шага на схеме
валюты Terra, соседний абзац `[[DOCX_IMAGE_img_031]]`. Роль абзаца — `body`, регион —
`prose`: текстовый слой PDF не даёт документному слою никакого другого сигнала. Модель
вернула `2b` без изменений совершенно правильно. Прогон умер, потеряв $0,21, при
`omitted=0` и `source_restored=0` — то есть не потеряв на книге ни одного абзаца текста.

**48 блоков против 1 абзаца (value_of_everything).** Обе величины верны и считают разное.
Перекрёстная сверка per-block диагностик прогона (`.run/block_fallbacks/*.json`) с
подготовленными заданиями даёт: все 48 блоков целиком лежат в регионе `back_matter`
(состав ролей — 107 `body`, 4 `list`, 2 `heading`), прозы среди них **0**. Это
библиография, примечания и URL — для них доставка исходника и есть правильный исход.
Один абзац / 63 символа канала части B — это единственный `omitted` абзац прогона
(`paragraph_disposition_counts.omitted = 1`), и он к тем 48 блокам отношения не имеет.

**9 символов на money_sustainability.** Блок 2 из 338: `# %` / `( i)` — титульная
страница, оба абзаца в регионе `front_matter`. Канал части B молчал по двум причинам
сразу: ни один абзац прогона не получил статус `omitted`/`source_restored`, а блок,
доставленный исходником, вообще не имеет пер-абзацной записи о подстановке. Механизм
закрыт (`quality_gate.build_source_text_delivery_facts` теперь принимает записи от
пайплайна), но на ЭТОЙ книге канал по-прежнему молчит — и это правильно: аппарат не проза.
