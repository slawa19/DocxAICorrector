# Как вызывать Codex для независимого аудита

**Зачем.** После крупной пачки работы её отдают на ревью другой модели. Codex ходит другим движком и
видит то, чего не видит внутренний цикл. Проверено: 2026-08-01 он нашёл шесть настоящих замечаний в
работе, уже прошедшей три внутренних адверсариальных круга; 2026-08-09 — дефект, который убивал бы
здоровый прогон на дефолтной операции, и класс блоков, который пропустили два независимых скрипта.

**Этот файл — про то, КАК его запустить.** Роль, которую ему при этом дают, описана отдельно в
[`codex-orchestrator-rule.md`](codex-orchestrator-rule.md) — это разные вещи.

---

## 1. Найти бинарь. Никогда не хардкодить путь

Рядом лежат ДВА исполняемых файла, и верхний — **нерабочий**: он падает на текущем конфиге
(`service_tier`, `model_reasoning_effort`), а после обхода этого API отвечает «модель требует более
новой версии Codex». Нужен тот, что в **версионном подкаталоге**.

**Хеш подкаталога меняется при каждом обновлении Codex.** Наблюдалось: `69066b736e1e17a4`
(2026-08-01) → `d7e8094cfb76a267` (2026-08-04) → `cfac6bda2d141e07` (2026-08-09, сменился в середине
рабочего дня). Поэтому путь **вычисляют каждый раз**, а не переписывают из старой заметки:

```powershell
$codex = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin" -Recurse -Filter codex.exe |
          Where-Object { $_.DirectoryName -ne "$env:LOCALAPPDATA\OpenAI\Codex\bin" } |
          Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
& $codex --version     # проверка: codex-cli 0.147.0-alpha.6.5 или новее
```

Фильтр `Where-Object` отбрасывает как раз старый файл, лежащий прямо в `bin\`. Ни один из них не
прописан в `PATH` — вызывать только по полному пути.

Модель и усилие уже заданы в `~/.codex/config.toml` (`model = "gpt-5.6-sol"`,
`model_reasoning_effort = "high"`), поэтому флаги модели не нужны.

## 2. Запустить

```
<codex.exe> exec --sandbox read-only - < prompt.txt
```

- `exec` — неинтерактивный режим, единственный пригодный для ревью.
- `--sandbox read-only` — он не изменит репозиторий. Это не мешает ему **выполнять** команды.
- `-` — промпт читается со stdin. **Промпт всегда через файл.** Длинный промпт, переданный
  аргументом, гибнет на кавычках PowerShell; на это уже потрачен цикл.

Из Git Bash то же самое:
```bash
"/c/Users/<user>/AppData/Local/OpenAI/Codex/bin/<hash>/codex.exe" exec --sandbox read-only - < prompt.txt
```

Один широкий проход по большой пачке — **порядка 20 минут и до полумиллиона токенов**. Не прерывать.
Запускать в фоне и заниматься другим.

## 3. Что он может и чего не может — это чинили дважды, оба раза неверно

| может | не может |
|---|---|
| читать **любой файл по абсолютному пути**, включая gitignored | работать в WSL (`Wsl/Service/E_ACCESSDENIED`) |
| **выполнять команды**, в том числе Python (проверено: 3.12.5, `MINGW64_NT`) | запускать наши тесты — им нужен venv в WSL |
| считать по данным сам, а не только рассуждать | — |

**Заметка «Codex ничего не может запустить, он только смотрит код» — НЕВЕРНА и стоила целого дня**
ручного счёта. Ошибка была в другом: «нет в git» приравняли к «недоступно». Дампы прогонов лежат
внутри каталога репозитория, просто в `.gitignore`, и читались всё это время.

**Практический вывод: давайте ему данные и просите СЧИТАТЬ.** 2026-08-09 на просьбе независимо
пересчитать величину, которую до этого считали два разных скрипта, он воспроизвёл её точно и нашёл
класс записей, который оба пропустили из-за необоснованного пропуска в коде.

## 4. Три грабли, каждая стоила цикла

1. **Адверсариальная формулировка отклоняется фильтром безопасности.** Промпт со словами «атакуй»,
   «сломай», «red team» умер с `This content was flagged for possible cybersecurity risk` — **после
   того как сжёг 120k токенов**. Переформулированный как «анализ устойчивости компонента в нашей
   собственной кодовой базе» отработал чисто и дал те же находки. Описывайте работу, а не атаку.
2. **Он ранжирует рассуждением, а не частотой.** 2026-08-09 три находки получили одинаковый P1, при
   том что одна срабатывала в 65 % случаев, а две другие требовали совпадения с событием, случающимся
   раз на 1 394. **Переранжируйте сами** — или прямо просите оценить частоту и сказать, чем он её
   мерил.
3. **Проверяйте каждую находку сами перед починкой.** Из шести находок первого прохода одна оказалась
   слабее заявленного, а первая попытка починить главную завела в репозиторий словарь слов и нарушила
   Конституцию VII.

## 5. Что писать в промпте (обязательный минимум)

- **Диапазон:** `git diff main...HEAD`, `git log --oneline main..HEAD`.
- **Что делает изменение** — своими словами, чтобы он не восстанавливал замысел по диффу.
- **Правила проекта, против которых проверять:** никаких списков слов, порогов на глаз и литералов из
  книги; детекция по региону / структурной роли / форме; двусторонний анти-вакуум; верификатор не
  является гейтом; прогон стоит денег, поэтому ложное падение — самый дорогой дефект.
- **Явно про его возможности:** «ты в том же окружении, читай файлы по абсолютным путям и считай сам;
  WSL тебе закрыт, наши тесты не запустишь».
- **Явно про честность:** «не выдумывай измерений; число, которого нет в файлах, называй прогнозом и
  говори, чем его проверить».
- **Явно про тон:** «возражение с конкретной ссылкой `файл:строка` ценнее согласия; если всё в
  порядке — скажи это коротко, не сочиняй находок ради объёма».
- **Формат ответа:** место, в чём дефект, при каком конкретном входе проявится, уверенность; отдельно
  — что нельзя решить по коду и надо проверять прогоном.

## 6. Если бинаря нет (облачный контейнер, чужая VM, Linux без Windows-хоста)

Codex установлен на Windows-хосте оператора. Сессия, у которой нет доступа к этому хосту, запустить
его **не может** — и обходить это самодеятельностью не надо.

Честные варианты, по убыванию предпочтительности:

1. **Оператор запускает Codex сам по вашему промпту.** Вы готовите файл промпта по разделу 5 и
   отдаёте его; получаете сырой вывод и разбираете. Ревью остаётся независимым — важно, чтобы промпт
   и разбор были ваши, а не чтобы процесс запустили ваши руки.
2. **Продолжать без Codex, назвав это вслух.** Независимого ревью не было — так и пишите в отчёте.
   Молча пропустить его хуже, чем пропустить явно: следующая сессия иначе решит, что пачка проверена.
3. **Ставить Codex в облаке под свой ключ** — только по прямому решению владельца: это его деньги и
   его учётная запись.

Чего делать нельзя: объявлять внутренний адверсариальный проход «независимым ревью». Ценность Codex
именно в другом движке; свой второй проход этой ценности не даёт.

## 7. Когда запускать

После **крупной пачки**, не после каждой задачи. Триггер вместо чутья: как только
`git log --oneline --no-merges <последний-проверенный>..main` набирает примерно 5 коммитов, или как
только в пачке появился новый производственный модуль либо детектор.

**Последний проверенный SHA держат в заметках сессии, а не в репозитории** — он меняется при каждом
проходе, а такие значения здесь не хранятся (то же правило, по которому в `WHERE_WE_ARE.md` нет ни
хеша `main`, ни чисел тестов). На 2026-08-09 проверено по `a5547a3` включительно. Именно диапазон и
делает ревью дешёвым и точным: без него Codex перечитывает всё и тонет.
