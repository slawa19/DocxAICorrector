**1. P1 — тайм-аут конвертации не гарантирует завершения группы процессов и возврата управления.**

В [external_process.py:106](src/docxaicorrector/runtime/external_process.py:106) ожидается завершение только родительского процесса. `SIGKILL` группе отправляется лишь тогда, когда именно этот `wait()` превышает тайм-аут. Если родитель завершился после `SIGTERM`, а потомок остался работать и удерживает stdout/stderr, принудительного завершения группы не будет. Затем [external_process.py:52](src/docxaicorrector/runtime/external_process.py:52) вызывает `communicate()` **без ограничения времени**.

Последствие: экспорт PDF может навсегда задержать выдачу уже подготовленных TXT/DOCX; потомок и временный каталог останутся жить. Это противоречит гарантии неблокирующего отказа PDF.

Проверка точного тела функции в изолированной модели подтвердила: при завершившемся родителе отправляется только `SIGTERM`. **Зависание настоящего LibreOffice не воспроизводилось; частота — прогноз**, условие: тайм-аут плюс переживший родителя потомок. **Уверенность высокая в дефекте управления процессами**, встречаемость такого состояния LibreOffice не измерена.

[Test:224](tests/test_spec_072_narration_pdf.py:224) подменяет сам `terminate_process_tree`, поэтому проверяет вызов помощника, а не уничтожение группы. Нужны завершение группы независимо от состояния лидера, ограниченный сбор вывода и Linux-тест с переживающим родителя потомком.

**2. P1 — частично записанный временный файл выпадает из отката и retention.**

В [artifacts.py:207](src/docxaicorrector/runtime/artifacts.py:207) запись выполняется **до** добавления текущего пути в `staged` на строке 210. Если запись успела создать файл и затем выбросила `OSError`, обработчик очищает предыдущие файлы, но пропускает текущий.

Остаток вида `*.result.tts.pdf.tmp.<id>` не распознаётся и последующей очисткой: [artifact_retention.py:242](src/docxaicorrector/runtime/artifact_retention.py:242) принимает только окончания из зарегистрированного списка. Это обработанная ошибка записи, а не исключённый из гарантий аварийный обрыв процесса.

Изолированная модель точной функции с частичной записью и последующим `OSError` оставила временный файл. **Частота — прогноз при частичной записи с ошибкой диска/I/O; статистики продуктовых прогонов нет. Уверенность высокая.** P1 соответствует заданной шкале утечек файлов; потерю текста в выдаче здесь не утверждаю.

[Test:115](tests/test_spec_072_result_group.py:115) бросает исключение до создания файла: его утверждение об отсутствии временных файлов этот сценарий не проверяет. Нужно учитывать текущий temp до начала записи и добавить отказ после фактической частичной записи.

**3. P2 — финализация раннера удаляет новые поля из manifest `latest`.**

[run_lietaer_validation.py:1637](tests/artifacts/real_document_pipeline/run_lietaer_validation.py:1637) записывает `latest_tts_docx` и `latest_tts_pdf`. Но сразу после этого вызывается [tracker.finalize():6955](tests/artifacts/real_document_pipeline/run_lietaer_validation.py:6955), который через `_write_locked()` заново записывает manifest. Его сборщик [на строке 1494](tests/artifacts/real_document_pipeline/run_lietaer_validation.py:1494) этих полей не содержит.

Таким образом, файлы скопированы и основной report содержит пути, но **окончательный manifest нарушает [контракт:72](specs/072-narration-docx-pdf/contracts/events.md:72)**.

В модели текущих методов после `finalize()` новые ключи исчезли. **Частота — прогноз для каждого запуска, дошедшего до этой финализации; вывод детерминирован порядком вызовов, продуктового замера ещё нет. Уверенность высокая.**

[Test:8300](tests/test_real_document_pipeline_validation.py:8300) читает manifest непосредственно после копирования, не выполняя последующую финализацию. Поля должны принадлежать состоянию tracker и сохраняться при его перезаписи; проверка должна доходить до окончательного manifest.

**4. P2 — после отказа нового экспорта `latest` сохраняет DOCX/PDF предыдущего запуска.**

В [run_lietaer_validation.py:1622](tests/artifacts/real_document_pipeline/run_lietaer_validation.py:1622) присутствует только копирование собранных форматов. Удаления прежнего файла при отсутствии нового нет. Модель последовательности «старый PDF → новый запуск без PDF» сохранила старый файл. **Частота — прогноз для такого перехода при совпадающем пути `latest`; продуктовая частота не измерена. Уверенность высокая.**
